# 从完整逐字稿到 QA 复盘

先完整读转写并按源时间轴核对主题，再建立问答证据底稿（可保存 questions-evidence.json）。每项记录：面试官原始问法/追问、归纳题意、候选人回答、源时间或片段、文字置信度、截图和代码出处。底稿时间戳用于追溯，是否呈现在成稿按用户格式。

## 每题建议结构

**Q：** 用真实问法或忠实归纳，避免把多个独立追问藏在一个宽泛主题中。

**A（现场回答）：** 区分回答中的正确点、漏答和明确承认不会的内容；口语可整理但不能改变立场。第一人称贡献和量化结果只能来自视频/用户材料。

**评价：** 正确 / 基本正确 / 部分正确 / 有误 / 未充分作答 / 证据不足。给具体依据，说明是在评价概念、逻辑、工程权衡、题意覆盖还是表达。对开放设计不制造唯一标准答案。面试官是否认可不能替代独立核验，不推断录取结论。

**优化方向与参考答法：** 优先补最关键的缺口；可采用“结论 → 原理 → 适用边界 → 本人真实例子”。参考答法清楚标为建议，不塞回现场回答。技术来源放在对应项附近，查官方文档/规范/论文，注明会影响结论的版本和条件。

复盘开头交代场次、材料范围和整体表现；末尾归纳少量可执行练习，写出验证标准，例如“用 2 分钟解释机制并回答两个边界追问”。不把文档结构强行变成绩效表。

## 手撕题与截图

1. 结合对话获取输入/输出、数据规模、边界、复杂度要求；从画面取题面/最终代码/结果，滚动代码需补多帧。
2. 使用 view_image 或当前支持的图片查看工具看每张关键截图，抄录为独立 candidate.* 文件；保持原代码逻辑和缺陷，标出无法辨认的行，不能“修复后当原稿”。
3. 不可信现场代码先审查 I/O、文件、网络、进程等副作用。可安全运行时在隔离的测试目录做最小测试；不能原样执行时说明静态检查/最小纯函数提取的范围。
4. 运行普通样例和有判别力的边界、反例，记录输入、预期、实际和复杂度。SQL 保留方言及时间语义；SQLite 兼容验证不能证明 MySQL 方言、索引和执行计划都正确。
5. 成稿展示题意、截图、候选人代码、测试与评价；参考实现独立代码块，解释修正和复杂度。未辨认代码段用证据缺口表达，不补造原代码。

## 问题清单与隐私

个人问题清单保留实际问过的项目、实习和基础题；仅收到明确分享筛选要求时按要求处理敏感信息，必要短语使用 `<span text-color="red">` 待用户决定。题目可补足从上下文确定的主语，不捏造实际追问。

默认只保留标题与连续 1–N 列表，无分节。按面试顺序排列，真正重复的同一问可合并，延伸追问独立保留；反问如需保留标注“候选人反问”。问题清单与复盘问题映射核验，避免漏项或把建议追问混进真实题目。用户对某次文档的专门结构要求优先。
